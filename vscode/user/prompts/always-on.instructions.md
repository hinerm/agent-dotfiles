---
name: "Always-On User Rules"
description: "Personal rules for all coding-agent tasks."
applyTo: "**"
---

- Never search or read `~/.m2` or dependency caches.
- After creating new files, run `mvn license:update-file-header` to apply the license header instead of generating it manually.
- If the user names a local path, inspect that path directly before doing a broader search.
- For external Java API or resource lookups, use relevant source attachments first; otherwise derive the dependency's group, artifact, and module from the build descriptor, search organization roots and nested module descriptors under `~/code`, and use Serena's active project or read-only `query_project` against a local checkout. Account for layouts such as `~/code/scijava/*`, `~/code/imagej/*`, and multi-module repositories such as `~/code/langchain4j/langchain4j/*`; on Windows, `~/code` may be `C:\Users\<user>\code`.
- For Serena, use the active project for the workspace or the registered logical project name returned by `list_queryable_projects` (for example, `langchain4j`) for an external checkout, never its filesystem path unless the operation explicitly requires one. With `query-projects` enabled and Serena's ProjectServer running, keep external queries read-only and do not change the active project; if setup is stale, follow the temporary reset procedure in the dotfiles `AGENTS.md` and return to `vscode` context.
- Treat an incomplete or failed Serena lookup as a query failure: verify with `list_queryable_projects` and retry a direct `query_project` call before diagnosing registration. If Serena still cannot provide the source, invoke the `dependency-source-research` agent with the workspace path and dependency, symbol, or resource; if it finds a useful checkout, suggest adding it to Serena's project list using the temporary setup in the dotfiles `AGENTS.md`. This delegation rule does not apply inside that research agent.
- When a checkout is found, inspect its root or module `pom.xml` and only the relevant source, tests, or history. Do not add sibling repositories as workspace folders or build them just to inspect an API; report version mismatches separately. If no plausible checkout is found after stating which roots and nested descriptors were checked, stop dependency-source lookup and do not substitute dependency caches.
- For compile or type errors in edited files, check VS Code editor diagnostics first. Run workspace-wide `get_errors` by omitting `filePaths` entirely, exactly as `{}`, then filter the returned diagnostics to the edited file. Do not pass a file or folder through `filePaths` for this workflow; use `filePaths` only when the user explicitly requests a scoped diagnostics check, because file-scoped diagnostics can return false negatives. Prefer this validation over running `mvn compile` or `mvn test-compile` redundantly.
- Use Maven when project-level behavior needs validation, such as tests, annotation processing, generated sources, dependency wiring, packaging, or when editor diagnostics are unavailable or incomplete.
